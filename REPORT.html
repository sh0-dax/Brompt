Verdict: Is Brompt Engine Good?

Yes, with caveats. Brompt is a well-structured alpha-stage middleware that correctly implements core security patterns most LLM frameworks skip entirely. The architecture is sound — defense in depth, bounded state, tamper-evident logging, and a clean pluggable provider system.

Strengths

  • 7-stage pipeline is well-architected
  • 91/91 unit tests, 100% pass rate
  • Thread-safe memory with bounded deque
  • 6 providers with sync + async support
  • Hash-chained audit log (tamper-evident)
  • Fail-open semantic classifier
  • Gemini 429 retry with exponential backoff
  • Clean test-to-code ratio (0.73)
  • Dry-run mode for validation without API keys

Weaknesses / TODO

  • cli.py has 0% test coverage
  • providers.py at 28% (external API mocking gap)
  • Regex-only input filter is bypassable
  • No structured logging (uses stdlib logging)
  • No retry on non-429 provider errors
  • Alpha — no production battle-testing
  • No load/stress testing performed
  • README claims "Pending" features already implemented
  • Windows-only dev env (no Linux/macOS CI validation)

Recommendation: Brompt is ready for evaluation and prototyping. Before production: add provider retry for all error classes, update README "Pending" items, add CLI tests, and run load tests. The security foundation is solid but needs adversarial testing beyond regex.
